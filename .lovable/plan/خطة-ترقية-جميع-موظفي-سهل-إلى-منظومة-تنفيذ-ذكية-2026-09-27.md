# خطة ترقية جميع موظفي «سهل» إلى منظومة تنفيذ ذكية

## النتيجة
كل موظف سيتعامل مع الطلب كعمل متكامل: يفهم الهدف، يختار الأدلة والأدوات المناسبة، ينفّذ، يراجع الناتج، يصلح النقص، ثم يجهّز الإجراء الحقيقي لاعتماد المالك. سيبقى نموذج الشات الحالي مؤقتاً كما طلبت.

## ما سنبنيه
1. **مخطط طلب موحّد لكل الموظفين**
   - تصنيف تعقيد الطلب ومخاطره وما يحتاجه من بحث حي أو بحث عميق أو أدوات أو متصفح.
   - تحديد المطلوب بالعدد، معيار النجاح، والحقائق التي يجب التحقق منها قبل الكتابة.
   - استخدام نفس الخطة في المحادثات والقدرات والمهام المجدولة.

2. **حلقة تنفيذ ومراجعة حقيقية**
   - مسار محدود: خطة ← أدلة وأدوات ← مسودة ← نقد ← إصلاح ← تحقق نهائي.
   - عند اكتشاف حقيقة ناقصة، يعود الموظف للبحث بدلاً من تغطية النقص بكلام عام.
   - حد أقصى واضح للجولات والوقت، مع تسليم أفضل نسخة موثوقة بدلاً من تعليق المحادثة.

3. **ذكاء تخصصي موحّد للستة**
   - سِراج: إشارة حقيقية، زاوية، حزمة نشر، وقياس.
   - نور: نية بحث، فجوات منافسين، مصادر، وسكيما وخطة نشر.
   - أمَل: نتيجة واحدة للرسالة، متابعة، تعارضات المواعيد، وتوقف آمن.
   - سالم: إشارة بيع، اعتراض حقيقي، مقارنة موثقة، وخطوة إغلاق محددة.
   - دانة: رسالة بصرية، مواصفات قابلة للتنفيذ، بديل مفاهيمي، وتوليد فعلي عند الطلب.
   - آدم: فصل الحقيقة عن التفسير، ثقة، قرار ميزانية، واختبار قابل للقياس.

4. **ذاكرة وتعلّم في كل مسار**
   - تطبيق قرارات المالك ودروس التعديلات والأمثلة المعتمدة في الشات والمهام التلقائية معاً.
   - الاحتفاظ بالتعلّم الحِرفي خاصاً بصاحبه، ومشاركة تفضيلات العلامة الآمنة مع الفريق.
   - تسجيل نتيجة المراجعة والتنفيذ لتغذية دورة التعلّم دون اختلاق درجات جودة.

5. **متابعة طبيعية داخل الشات**
   - استمرار سياق المخرج والإجراء عند «عدّل»، «ابعت»، «رد»، أو تعليمات متابعة بصياغة طبيعية.
   - السماح بنسخة معدلة جديدة بعد تنفيذ سابق، مع اعتماد جديد ومنع الإرسال المكرر غير المقصود.
   - عدم إسقاط الرسالة أثناء انشغال الموظف؛ توضيح حالتها للمستخدم.

6. **صدق التنفيذ والتحقق**
   - عدم اعتبار النقر على زر نجاحاً؛ فحص نتيجة الصفحة أو استجابة الخدمة قبل إعلان الإرسال.
   - إظهار حالة: تم التحقق، يحتاج تأكيداً، توقف آمن، أو فشل مع سبب مفهوم.
   - إبقاء الدفع والنشر والإرسال والالتزامات الحساسة خلف موافقة المالك.

7. **اختبارات قبول شاملة**
   - حالات واقعية لكل موظف: سؤال، مهمة قصيرة، تقرير عميق، رابط، نقص بيانات، وتعديل.
   - اختبار البحث وTavily والمتصفح، التحويل بين الموظفين، الاعتماد، التعديل ثم الإرسال، والفشل.
   - قياس الاكتمال، صحة المصادر، عدم الادعاء، جودة العربية، وزمن الاستجابة.

## تفاصيل تقنية
- إضافة وحدة تخطيط خالصة وآمنة تُنتج قراراً منظماً، وتُستخدم كمصدر واحد لبوابات البحث والأدوات وعمق التفكير.
- توسيع حَكَم الجودة إلى جولتين كحد أقصى، مع ميزانية زمنية وتدقيق حتمي بعد كل إصلاح.
- ربط فجوات الحقائق بخدمة البحث الحالية عبر callback اختياري، بلا تغيير نموذج الشات.
- تمرير الذاكرة التشغيلية والقرارات والدروس إلى مسارات الجدولة والتشغيل التلقائي مثل مسار المحادثة.
- تحسين دورة الإجراء داخل المحادثة والتحقق من نتائج المتصفح والخدمات مع الحفاظ على سجل التدقيق.
- عدم تغيير واجهة الشات جذرياً الآن؛ اختيار النموذج وتصميم الشات المحترم مرحلة لاحقة كما طلبت.

## خارج هذه المرحلة
- تغيير مزوّد أو نموذج الشات.
- نشر الموقع أو إضافة تكاليف خارجية جديدة.
- إجراء دفع أو إرسال أو نشر بلا اعتماد صريح.
